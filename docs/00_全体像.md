# THE ROOMS 全体像

## 何を作るか

スマホのブラウザで遊べる、広告なしの配置パズル。元にしたのは Meowdoku(Oakever Games)で、仕組みは LinkedIn の Queens と同じ系統である。

- 盤は N×N で、N 個の「部屋」に分かれている(部屋は色で見分ける)。
- 各行・各列・各部屋に駒をちょうど 1 つ置く。
- 駒どうしは隣り合えない(斜めも含む 8 方向)。
- 面はすべて解がちょうど 1 つ。だから「ここしかない」場所を順に見つけていけば、必ず解ける。

駒は desktop-mate のキャラクター「ステロペ」。画面の下で表情を変えて、短い一言を添える。見た目は名家の書斎(暗い胡桃材・金・藍)に寄せた。

## 役割分担

| 場所 | 言語 | 担当 |
|---|---|---|
| `generator/` | Haskell | ルールの正本。面の生成、唯一解の保証、推論による難易度付け、テストベクタの出力 |
| `web/` | JavaScript | 画面、入力、得点、演出、音、ステロペ。ルールとソルバは Haskell の移植で、ベクタとの一致をテストで確かめる |
| `docs/` | Markdown | この解説 |

## 面の作り方(Haskell)

1. **正解の配置を作る**: 行ごとに、置ける列から乱数で 1 つ選ぶ。行き詰まったらやり直す。
2. **部屋を育てる**: 駒のマスを種にして、ランダムに選んだ部屋の隣の空きマスを 1 つずつ取り込む。空きマスが無くなるまで続ける。
3. **解を 1 つにする**: 解が 2 つ以上あれば、正解でない解にあって正解に無い駒のマスを、隣の部屋へ移す。移した先の部屋に駒が 2 つになるので、その解は成り立たなくなる。正解の駒は動かさないので、正解はそのまま解であり続ける。部屋がちぎれないことだけ確かめる。
4. **難易度を測る**: 下の推論規則で解けるかを調べる。基本の 2 規則で解ければ 0、2 部屋の規則が要れば 1、それでも解けなければ(仮置きが要れば)2。Stage が進むほど大きい盤・高い難易度を許す。

乱数は線形合同法を自分で書いているので、同じシードから同じ面ができる。

## 推論の規則(人の解き方をまねたもの)

候補 = まだ駒を置けるかもしれないマス。駒を置くと、その駒とぶつかるマス(同じ行・列・部屋、隣)は候補から消える。

- **Forced**: ある行・列・部屋の候補が 1 つだけなら、そこに置く。
- **Squeeze**: ある行・列・部屋のすべての候補とぶつかるマスには置けない。たとえば部屋の候補が 1 行に収まっていれば、その行の他のマスは消える。
- **Pair**: 2 つの部屋の候補が合わせて 2 つの行(列)に収まるなら、その 2 行(列)の他の部屋のマスは消える。

どの規則も正しい事実しか導かないので、適用する順番が違っても最後に残る候補は同じになる。この性質のおかげで、Haskell と JavaScript の結果を突き合わせられる。Hint はこの推論で最初に確定する駒の位置を示す。

## 遊びの設計(リスクとリターン)

| 要素 | リスク | リターン |
|---|---|---|
| 駒を置く | 間違えると Heart −1、Chain が切れる | 正しければ 100 × Chain 倍率。倍率は ×1.5 から ×5.0 まで |
| × の印 | なし(いくら付けてもよい) | 考えを整理できる。駒を置くとぶつかるマスに自動で付く |
| Hint | Chain が切れ、Score −200。1 Stage に 3 回まで。Perfect でなくなる | 次に必ず置ける場所が分かる |
| 時間 | なし(制限はしない) | 目標時間(N × 12 秒)より早いと 1 秒ごとに +10 |
| Perfect | — | 間違いも Hint も無しで +1000 と Heart +1 |
| Heart | 尽きると World(5 Stage)の先頭からやり直し。Run の Score は 0 に | Best Run として記録が残る |

Stage は 50。5×5 から始まり、10 Stage ごとに 1 つ大きくなって 10×10 まで。各 Stage に 3 面あり、あきらめると別の面になる。
